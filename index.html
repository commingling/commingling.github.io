📘 01. 软件架构质量属性与 ATAM 评估模型

架构设计本质是对质量属性（Quality Attributes）的权衡与取舍。在系统架构设计师考纲中，核心聚焦以下六大属性战术：

  • 性能 (Performance)：资源调度、计算异步化、热点分流、多级缓存（本地 Caffeine + 集中式 Redis）、数据库读写分离与索引优化。
  • 可用性 (Availability)：心跳检测、双机热备、集群无状态化、故障转移、服务熔断降级（Sentinel）与幂等自愈。
  • 安全性 (Security)：身份鉴权、非对称签名防篡改、参数白名单与 SQL 防注入、敏感数据脱敏加密存储。
  • ATAM 架构评估模型：通过效用树（Utility Tree）梳理优先级，精准识别系统的敏感点（Sensitivity Points）、权衡点（Trade-off Points）与风险点。
🏛️ 02. 现代分布式与云原生架构演进

传统单体向微服务与云原生转型的架构模式沉淀：

  • 服务解耦与治理：基于 Dubbo3 / Spring Cloud 的服务发现与 RPC 编排，API 网关负责路由分发与鉴权。
  • 分布式数据层：分库分表键（Sharding Key）设计、分布式自增 ID（优化版 Snowflake 防时钟回拨）、TiDB HTAP 混合架构。
  • 云原生三要素：基于 Docker/K8s 容器化编排、声明式 API 与 Service Mesh 流量治理。
✍️ 03. 架构论文黄金三段论与万能工程论据库

Engineering Trade-offs

架构选型与权衡决策模型

资深架构师的核心壁垒在于对复杂场景下「利弊取舍」的精准把握。

方案类型 业务侵入性 吞吐量与延迟影响 一致性级别 补偿与回滚成本 推荐业务场景
本地消息表 + MQ 中等 极小 (异步解耦) 最终一致性 (BASE) 简单 (重试+人工补偿) 支付成功后发货、积分增减、风控通知等异步链路
Seata AT 模式 极低 (注解级) 中等 (全局锁排队) 准强一致性 自动化 (全局事务回滚) 中台内部微服务间读多写少、跨库更新订单表
TCC (Try-Confirm-Cancel) 极高 (需手写3个方法) 小 (业务自持锁) 强最终一致性 业务自主严格补偿 核心资金划扣、跨机构账务冻结与解冻
SAGA 长事务 高 (需定义补偿动作) 小 (无隔离性阻塞) 最终一致性 逆向补偿流程 长周期跨部门履约、机票酒店复合打包预订
方案类型 写入性能 脏读时间窗口 实现复杂度 极端并发击穿防护 推荐业务场景
Cache Aside (先更库再删缓存) 极高 微秒级 (极短) 极低 配合互斥锁 / 逻辑过期 绝大多数读多写少的基础业务数据、配置中心
延迟双删 (Del -> DB -> Sleep -> Del) 中等 (受Sleep耗时影响) 极短 较低 可缓解主从延迟引发的脏读 存在 MySQL 主从复制延迟 (Replica Lag) 的中小型系统
Canal 监听 Binlog 异步刷新 最高 (业务无需删缓存) 取决于 MQ 消费时延 中高 (需维护 Canal 集群) 异步兜底平滑无毛刺 核心商品详情页、千万级大促主数据多级缓存同步
方案类型 并发阻断能力 网络开销 时钟与死锁风险 回滚容错机制 典型应用场景
数据库唯一索引 (Unique Index) 强一致性 (兜底之王) 零额外网络通信 无死锁风险 事务自然回滚 流水号防重、防重复建单、对账表主键
Redis 分布式锁 (SETNX + Lua) 毫秒级提前拦截 微量 Redis RTT (1~2ms) 需配置合理租期与 Watchdog finally 块中安全释放锁 秒杀减库存、订单支付前置排重校验
前置 Token 令牌机制 请求发出前阻断 增加一次 Token 获取请求 Token 消费即失效，无死锁 业务失败需根据需要恢复 前端表单防手抖连续点击、防浏览器多次刷新
